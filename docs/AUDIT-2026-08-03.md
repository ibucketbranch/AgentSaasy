# Docs-vs-code audit, 2026-08-03

Record of what was checked in this repo, what was found, what changed, and what
is still open. Written so an agent picking this repo up cold does not have to
redo the verification.

**Read this before editing any claim in the docs.** Several numbers here look
wrong at a glance and are correct once scoped. Several look fine and are not.

## Scope and method

Subject: `~/Projects/AgentSaaSy` at commit `44be548`, branch `main`, private
GitHub repo `ibucketbranch/AgentSaaSy_EAM`.

The question was whether the documentation claims more than the code does.
Every factual claim was checked against the source with a command, not read
for plausibility. Test counts were reproduced by running the suite, not
trusted from a doc. Where a claim survived, it is listed as verified.

An earlier advisory pass by the local Hermes model was discarded. It reported
10,458 lines of code (actual 5,590), 34 tests (actual 59), a 610-line GIS tool
(actual 232), and cited a `DEPLOYMENT-SUMMARY` file that does not exist. It
also stated that items in commit `a5a4955` were absent from HEAD when
`git merge-base --is-ancestor a5a4955 HEAD` confirms they are present. Do not
reuse that output.

## What was verified as accurate

- 7 `@tool` decorators in `agent.py` at lines 149, 219, 274, 347, 413, 481, 652.
- `data/asset_data.csv` holds exactly 50 records.
- LangChain plus `gpt-4o-mini` in source, matching the docs.
- Monte Carlo capital planning is genuinely implemented. `simulate_strategy`
  at `agent.py:755` runs a real iteration loop with a 1,000-iteration default
  and produces P10/P50/P90. An earlier review claimed this "lacks actual
  simulation runs"; that claim is false.
- `scipy.stats` is legitimately used, `zscore` at `agent.py:322`.
- Full test suite passes. Verified twice by running it: 59 passed, once before
  the edits below and once after.

## Findings and what was changed

### 1. Routing is a scenario model, the docs sold it as a capability

The most consequential finding. `optimize_field_routes` does substring matching
on location names and multiplies by constants: `baseline_drive_time_per_job = 45`
and `optimization_multipliers = {"minimize_drive_time": 0.65, ...}`. The 35
percent reduction is not computed, it is the input assumption. The code says so
in its own comments at `agent.py:533-534` (`# SPATIAL ANALYSIS SIMULATION`,
`# In production: Use PostGIS spatial clustering (DBSCAN)`).

`TECHNICAL-WHITE-PAPER.md` was already honest about this at lines 427, 977, and
988. `README.md`, `GIS-FEATURE-SUMMARY.md`, `TOOLS-REFERENCE.md`, and
`DEPLOYMENT-STATUS.md` were not, so the repo contradicted its own white paper.

Changed: added simulation qualifiers to every unqualified statement of the
20-40 percent figure, relabeled "Typical Results" and "Key Benefits" as
"Modeled Results" and "Modeled Benefits", replaced "Route optimization with
constraint satisfaction" (there is no constraint solver) with an accurate
description, and put a scope note at the top of the Business Impact Summary in
`TOOLS-REFERENCE.md`.

Also changed the runtime output. `agent.py:635-639` printed a block headed
"GIS INTEGRATION" listing ESRI, PostGIS, and OSRM as though they were in use.
It now reads "PRODUCTION INTEGRATION DESIGN (none of this is implemented here)".

### 2. The white paper contradicted itself on regression

`TECHNICAL-WHITE-PAPER.md:62` said TCO analysis uses "regression-based
projection". Line 118 of the same document said regression is reserved for
Phase 2. Commit `a5a4955` fixed 118 and missed 62. Line 62 now matches.

### 3. The NGAI sweep in `a5a4955` matched only one casing

The commit message says "sweep remaining NGAI/NexGen from dev docs and code".
It caught `NexGen` and `AgentSaasy_NGAI` in root-level docs. It did not catch
the all-caps `NEXGEN`, which survived in 34 places including five runtime
strings in `agent.py`, seven in `demo_showcase.py`, and fourteen across
`prompts/`. It also left `AgentSaasy_NGAI` in `requirements.txt`, `LICENSE`,
`.cursor/rules/`, and `experiments/`.

The worst single instance was `experiments/STUDY-DESIGN.md:6`, which published
`**Repo:** github.com/ibucketbranch/AgentSaasy_NGAI` as a citation. That URL is
dead; the real remote is `AgentSaaSy_EAM`.

Changed: all repo-name references corrected, and the subject platform
anonymized (see next item).

### 4. Naming collision created by the previous sweep

`a5a4955` replaced the subject company's name with "AgentSaaSy", which is also
the name of this project. That left 39 places where "AgentSaaSy" meant the
subject platform, sitting next to places where it meant this repo. So
`GIS-OPTIMIZATION-GUIDE.md:5` referred to "AgentSaaSy Asset Management's ESRI
certification" (the subject) three lines from "AgentSaaSy + GIS Agent" (this
project), and "AgentSaaSy API" read as though this project exposes an API when
it meant the subject's API. `prompts/white_paper_prompt.md:15` documents
`{{platform_name}}` as a template variable, which is the tell.

Changed: the subject platform is now consistently "the EAM platform". This
repo keeps the name AgentSaaSy / AgentSaaSy_EAM. The two are no longer
ambiguous.

**Naming convention going forward:** the subject of the study is "the EAM
platform" or "the platform". Its CTO is "the platform CTO". Never reintroduce a
real company or person name into this repo, including in prompts and demo
strings. The people involved are real and the study is about a category, not
about them.

### 5. ESRI certification was asserted as fact with no implementation

`agent.py:636` and twelve doc locations asserted an ESRI ArcGIS System Ready
certification, including "Only EAM solution with certified ESRI integration".
There is no ESRI code in the repo. `grep -i "esri\|ortools\|osrm\|postgis\|dbscan"`
over the Python returns only comments and print strings. The certification is
also a claim about a third party's compliance status, sourced from conversation
rather than a public record.

Changed: every instance now reads as vendor-reported and unverified, and the
competitive claims are labeled positioning claims rather than facts.

### 6. Retired ROI multiples survived outside the white paper

`a5a4955` retired ROI multiples from `TECHNICAL-WHITE-PAPER.md` only. They
remained in `GIS-FEATURE-SUMMARY.md:35` and `:226` (50x-100x, "payback in 1-2
weeks"), `GIS-OPTIMIZATION-GUIDE.md:339` (50x), and
`DEPLOYMENT-STATUS-CAPITAL-PLANNING.md:18` and `:426` (2.7x).

Changed: all are now labeled unvalidated scenario models, matching the language
the white paper abstract already uses.

### 7. Test counts were stale in both directions

Reproduced by running the suite: `tests/test_agent.py` has 37 test functions,
`tests/test_capital_planning.py` has 22, total 59, all passing in about 150
seconds.

Four docs said 34, which is a generation behind. The white paper abstract said
37, which counts one file. Both undercount, so this was never an overclaim, but
it was inconsistent.

Changed: unqualified counts now say 59. Two places in the white paper correctly
scope 37 to tool functions only and were deliberately left alone:
`TECHNICAL-WHITE-PAPER.md:147` (NFR-04, "Test coverage (tool functions)") and
`:643`, which reproduces a verbatim pytest transcript of `test_agent.py`. Line
643 now states its scope explicitly so it does not read as a contradiction.

## Open items, deliberately not changed

- **Dead `sklearn` import.** `agent.py:50` imports `LinearRegression` and never
  instantiates it (`grep -c "LinearRegression("` returns 0). Left in place
  because `TECHNICAL-WHITE-PAPER.md:118` already documents it honestly as
  reserved for Phase 2. This is code hygiene, not a false claim. Removing it
  also means dropping `scikit-learn` from `requirements.txt`, which is a
  separate decision.

- **Em dashes** appear in `agent.py:68`, `prompts/AgentSaaSy_Agentic_Demo_Prompt.md`,
  and several prompt files. The owner's house style prohibits them. Not changed
  because these are his own drafted prose, not generated commentary.

- **`prompts/white_paper_prompt.md`** lines 225, 439, 457, and 475 describe the
  subject platform's stack including ESRI and PostGIS, and line 475 asserts
  "the GIS integration is in place". These are template inputs describing the
  subject rather than claims about this repo, so they were left, but they would
  need the same treatment if that template is ever used to generate a
  publishable document.

## Note for any agent working in this repo

The failure mode this audit exists to prevent is an agent reading the docs,
believing them, and building on a capability that is not there. The GIS tool
reads as a routing engine in the documentation and is a lookup table with
multipliers in the code. Check `agent.py` before trusting any capability claim
in a markdown file here.

A local 9-12B model was measured on 2026-08-03 reporting `6 passed in 0.01s`
for a pytest run it never performed, in a directory where it created no files.
Do not accept any agent's summary of work that produces files. Check the files.
